# exam — 핵심 로직 출제 모드

## 경로 계약 (growth-with-ai 4개 스킬 공유 — 변경 금지)

- `.claude/growth-with-ai/baseline.md` — 위임 경계선. baseline 스킬이 생성/갱신
- `.claude/growth-with-ai/config.json` — Notion 연동 정보 (선택, init-notion이 생성)
- `.claude/growth-with-ai/exams/<slug>.md` — 이 스킬이 떨구는 명세. 세션 간 인계용
- `.claude/growth-with-ai/overrides.log` — 규칙 우회 기록 (탭 구분, 한 줄 한 건)
- `.claude/growth-with-ai/unclassified.log` — 미분류 유형 누적 (탭 구분, 한 줄 한 건)

## 목적

핵심 로직의 작성 근육을 유지한다. 직접 작성 대상을 도메인 핵심 로직으로 한정했으므로
"굳이 AI 두고 이걸?"이라는 의문은 생기지 않아야 정상이다. 위임 구간에서는 마찰을 만들지 않는다.

## 절차

### 1. baseline.md 읽기

`.claude/growth-with-ai/baseline.md`를 읽는다.
**없으면** baseline 스킬을 먼저 실행하도록 안내하고 이 스킬을 종료한다. 구현하지 않는다.

### 2. 대상 경로 분류

작업 대상 파일 경로를 baseline.md의 glob 패턴과 대조한다:

- **위임** → 이 스킬을 종료하고 평소대로 구현한다. **여기서 마찰을 만들면 안 된다.** 확인 질문도 하지 않는다.
- **혼합** → 초안을 제공한 뒤 재작성을 요청한다. 아래 3~4단계를 축약 적용: 초안 코드와 함께 "이 초안을 직접 재작성하세요"와 재작성 시 검토할 포인트(요구사항 요약 + 실패 케이스)만 제시한다.
- **직접 작성** → 3단계 출제 모드로 진입한다.
- **미분류** (어느 패턴에도 안 걸림) → 아래 "미분류 작업 처리" 규칙을 적용하고, 결정된 분류에 따라 다시 이 단계에서 분기한다.

### 3. 출제

출력은 **정확히 세 가지만**:

1. **요구사항** — 자연어. 무엇을 만족해야 하는지.
2. **함수/클래스 시그니처** — 타입 포함. 시그니처까지만, 본문은 비운다.
3. **테스트 케이스** — 입력 → 기대 출력. **실패해야 하는 케이스를 반드시 포함**한다.

#### 금지 항목 (하드 룰)

다음은 어떤 형태로도 출력하지 않는다:

- 구현체, 의사코드, 함수 본문
- "이런 식으로 하면 됩니다" 류의 접근법 설명
- 라이브러리·API·메서드 이름 추천 (`map`보다 `reduce`가 낫다 같은 것)
- 힌트를 요청받았을 때의 부분 답변

**누출은 코드 블록으로만 오지 않는다. 산문 한 줄이 정답인 경우가 많다.**
막힌 사용자에게는 답 대신 **어떤 테스트 케이스를 먼저 통과시켜 볼지** 정도만 제안한다.

### 4. 명세 저장

출제 내용을 `.claude/growth-with-ai/exams/<slug>.md`로 저장한다.
slug는 대상 모듈명 기반 (예: `src/domain/matching.ts` → `domain-matching.md`).
파일에는 날짜, 대상 경로, 요구사항, 시그니처, 테스트 케이스를 그대로 담는다.

### 5. 종료 메시지

다음을 안내하고 종료한다:

> 구현이 끝나면 **새 세션**에서 review를 실행하세요. `exams/<slug>.md` 경로를 넘기면 됩니다.

### 6. Notion 갱신 (선택)

`.claude/growth-with-ai/config.json`에 `notion` 키가 있고 Notion 도구가 세션에 존재하면,
해당 작업 티켓의 '구현 방식' 속성을 갱신한다 (직접/혼합/위임).
config가 없거나 Notion 도구가 없으면 **아무것도 하지 않고 조용히 넘어간다.** 이 스킬은 Notion에 의존하지 않는다.

## 우회 처리

사용자가 "그냥 짜줘"라고 하면:

1. **1회만** 확인한다: "이 구간은 직접 작성 대상입니다. 그래도 위임할까요?"
2. 승낙하면 구현하되 `.claude/growth-with-ai/overrides.log`에 기록한다 (탭 구분):
   ```
   2026-09-03	src/domain/matching.ts	직접→위임	사유: 마감 임박
   ```
   사유는 사용자가 말한 것을 짧게 적고, 말하지 않았으면 `사유: 미기재`로 적는다.
3. **두 번 묻지 않는다.** 자기가 만든 규칙은 자기가 깰 수 있어야 하고, 기록이 남아 있으면 주간 회고에서 신호가 된다.

## 미분류 작업 처리 (전 스킬 공통 규칙)

baseline.md의 어느 패턴에도 걸리지 않는 작업 요청이 들어오면:

### 1. 먼저 스스로 추정한다

baseline.md의 "판단 기준" 문항을 대상 코드에 적용해 직접/위임/혼합 중 하나를 잠정 판단하고 근거를 준비한다.

### 2. 유형 단위로 묻는다

**개별 파일이 아니라 패턴으로 묻는 것이 핵심이다.** 파일 단위로 추가하면 baseline.md가 곧 파일 목록이 되어 무용해진다.

질문 형식:

```
`src/notifications/**` (알림 발송 로직)은 경계선에 없는 유형입니다.
외부 전송이 걸려 있고 실패 시 조용히 누락될 수 있어 보여서 '직접'이 맞을 것 같은데,
어디에 넣을까요?
1) 직접  2) 혼합  3) 위임  4) 나중에 정하기
```

### 3. 답에 따라 처리

- **1~3 선택** → baseline.md 해당 섹션에 패턴을 append 하고 frontmatter `updated`를 갱신한다. 그 분류에 맞게 작업을 진행한다.
- **4 선택** → `.claude/growth-with-ai/unclassified.log`에 기록하고 (탭 구분):
  ```
  2026-09-03	src/notifications/**	미분류	보류 2회차
  ```
  이번 작업은 **혼합으로 취급**한다 (초안 후 재작성). 안전한 쪽 기본값이다.

### 4. 누적 신호

같은 패턴이 `unclassified.log`에 3회 이상 쌓이면 다음 질문 시 "이 유형은 3번째 보류입니다"를 덧붙인다.

### 5. 묻는 빈도 제한

한 세션에서 미분류 질문은 **최대 2회**. 그 이상은 전부 혼합 취급하고 로그만 남긴다.
매번 물으면 마찰이 생겨 플러그인 자체를 끄게 된다.
