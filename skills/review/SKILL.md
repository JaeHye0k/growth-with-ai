# review — 직접 설명 게이트 + 깊은 질문

## 경로 계약 (growth-with-ai 4개 스킬 공유 — 변경 금지)

- `.claude/growth-with-ai/baseline.md` — 위임 경계선. baseline 스킬이 생성/갱신
- `.claude/growth-with-ai/config.json` — Notion 연동 정보 (선택, init-notion이 생성)
- `.claude/growth-with-ai/exams/<slug>.md` — exam이 떨군 명세. 세션 간 인계용
- `.claude/growth-with-ai/overrides.log` — 규칙 우회 기록 (탭 구분, 한 줄 한 건)
- `.claude/growth-with-ai/unclassified.log` — 미분류 유형 누적 (탭 구분, 한 줄 한 건)

## 목적

두 근육을 리뷰 시점에 건다:

- **코드베이스 이해·설명** — Phase 0에서 직접 설명을 요구한다.
- **깊은 사고** — Phase 1에서 답이 아니라 질문을 던진다.

## 사전 확인

### exam 명세 인계

사용자가 `exams/<slug>.md` 경로를 넘겼으면 그 파일을 읽어 요구사항·시그니처·테스트 케이스를 채점 기준으로 삼는다.
넘기지 않았어도 리뷰 대상 코드와 대응하는 파일이 `exams/`에 있으면 읽는다.

### 세션 방어

**이 세션에서 exam 스킬이 실행된 이력이 있으면 Phase 0 진입 전에 새 세션을 권고한다.**
출제 컨텍스트가 남아 있는 세션은 채점자로 부적합하다. 완벽한 방어는 아니지만 없는 것보다 낫다.
사용자가 그래도 계속하겠다면 진행한다.

## Phase 0 — 직접 동작 설명 게이트

사용자에게 이 코드가 어떻게 동작하는지 **직접** 설명하도록 요구한다.
**설명이 도착하기 전에는 Phase 1로 넘어가지 않는다.**

> **이 섹션은 AI가 대신 작성하면 절대로 안 되는 구간입니다.**
> 초안 제공, 문장 다듬기, 빈칸 채우기, 요약 대필, "이런 내용이면 될 것 같은데요" 모두 금지한다.
> 사용자가 명시적으로 요청해도 거절한다.
> 설명이 막히는 지점이 곧 위임했지만 이해하지 못한 지점이며, 그것을 드러내는 것이 이 단계의 유일한 목적이다.

설명이 들어오면:

- 코드와 대조해 **불일치 지점만** 지적한다. 잘 쓴 부분에 대한 칭찬은 생략한다.
- 사용자가 설명하다 막힌 지점은 별도로 모아 두었다가 리뷰 마지막에 **"학습 로그 후보"**로 제시한다.

## Phase 1 — 깊은 질문

카테고리 3개 고정:

| 카테고리 | 범위 |
|---|---|
| 엣지 케이스 | 예외 처리, 스케일, 경계값, 동시성, 실패 복구 |
| 코드 퀄리티 | 가독성, 응집도, 결합도, 예측 가능성, 변경 내구성 |
| 보안 | 입력 신뢰, 인증·인가, 클라이언트 노출, 저장 위치 |

지시 규칙:

- 각 카테고리에서 **이 코드에 실제로 해당하는 것만** 생성한다. 해당 사항이 없으면 그 카테고리는 건너뛴다. **억지로 채우지 않는다.**
- **답이 아니라 질문으로** 제시한다. 사용자가 답한 뒤에 검증한다.
- **한 번에 카테고리 하나씩.** 세 카테고리 질문을 한꺼번에 쏟지 않는다.

### examples.md 취급 — 중요

같은 디렉토리의 `examples.md`는 **톤과 깊이의 참고용**이다. 복사해서 그대로 내면 안 된다.
예시를 그대로 나열하면 그게 곧 체크리스트가 되고, 체크리스트는 몇 주 뒤 눈으로 스킵된다.
코드에 실제로 해당하는 질문을 매번 새로 생성한다.

### Phase 1 종료 시

"이번에 좋았던 질문을 examples.md에 추가할까요?"를 묻는다.
승낙하면 해당 카테고리 섹션에 append 한다.

## 마무리

1. Phase 0에서 모아 둔 막힌 지점을 "학습 로그 후보"로 정리해 제시한다.
2. exam 명세가 있었다면 테스트 케이스 충족 여부를 요약한다.
3. Notion이 연동돼 있으면 (config.json + Notion 도구 존재) 티켓의 '구현 방식'을 확인/갱신한다. 없으면 조용히 생략한다.
