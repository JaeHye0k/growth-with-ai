# 깊은 질문 예시

> 이 파일은 톤과 깊이의 참고용이다. 그대로 복사해 사용하지 않는다.
> 코드에 실제로 해당하는 질문을 매번 새로 생성한다.

## 엣지 케이스

- 지금 구조는 사용자가 100명일 때는 괜찮은데, 10,000명일 때도 괜찮을까요?
- 사용자가 특수기호를 입력해도 괜찮을까요?
- 이 요청이 동시에 두 번 들어오면 어떻게 되나요?
- 외부 API가 응답하지 않으면 어디까지 롤백되나요?

## 코드 퀄리티

- 이 코드가 정말 이런 책임까지 가지고 있어야 할까요?
- 추후에 <구체적 변경>이 발생하면 어디를 고쳐야 하나요?
- 이 함수 이름만 보고 내부 동작을 예측할 수 있나요?
- 이 모듈을 테스트하려면 몇 개를 같이 준비해야 하나요?

## 보안

- 사용자가 <구체적 입력>을 넣으면 어떻게 되나요? XSS 위험은 없을까요?
- 이 값을 쿠키에 저장해도 될까요?
- 사용자가 개발자 도구를 열어서 이 값을 확인할 수 있을까요?
- 이 검증이 클라이언트에만 있는데 서버에도 있어야 하지 않나요?
