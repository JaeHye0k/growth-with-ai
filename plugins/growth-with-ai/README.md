# growth-with-ai

AI에 코드 작성을 위임하면서 생기는 능력 저하(코드 작성력, 코드베이스 이해도, 검증 능력)를 막기 위한 Claude Code 플러그인.

## 핵심 전제

1. **의지 기반 액션 아이템은 실패한다.** "일주일에 한 번 직접 코딩"은 캘린더에 걸려 있고, 캘린더는 실제 업무와 경쟁해서 진다. 훅은 이미 하고 있는 작업 흐름 안에 걸려야 한다.
2. **직접 작성 대상이 단순 작업이면 무너진다.** "굳이 AI 두고 이걸?"이라는 의문은 대상이 보일러플레이트일 때만 생긴다. 직접 쓰는 대상을 도메인 핵심 로직으로 한정하면 의문 자체가 사라진다.

세 가지 근육을 각각 다른 시점에 건다:

| 근육 | 훅 시점 | 담당 스킬 |
|---|---|---|
| 핵심 로직 직접 작성 | 작업 시작 / 구현 요청 시 | `exam` |
| 코드베이스 이해·설명 | 리뷰 / 머지 직전 | `review` Phase 0 |
| 깊은 사고 | 리뷰 시 | `review` Phase 1 |

## 스킬

### baseline — 위임 경계선 설정

프로젝트마다 "직접 작성 / 혼합 / 위임" 경계선을 인터뷰로 설정한다. 저장소를 먼저 스캔해 초안을 제시한 뒤 질문으로 다듬는다. 산출물:

- `.claude/growth-with-ai/baseline.md` — glob 패턴 기반 경계선
- 프로젝트 `CLAUDE.md` 게이트 문장 — 스킬 자동 트리거는 확률적이므로 이 한 줄이 실질 강제 장치
- `.github/PULL_REQUEST_TEMPLATE.md`의 "직접 동작 설명" 섹션

### exam — 핵심 로직 출제 모드

구현 요청이 오면 baseline과 대조해 분류한다. **위임** 구간이면 마찰 없이 평소대로 구현하고, **직접 작성** 구간이면 구현체 대신 요구사항·시그니처·테스트 케이스만 출제한다. 구현체·의사코드·접근법 설명·API 추천은 어떤 형태로도 주지 않는다.

출제 명세는 `.claude/growth-with-ai/exams/<slug>.md`로 저장된다 — 채점(review)은 **새 세션**에서 한다. 같은 세션에서 출제자와 채점자를 겸하면 정답이 이미 컨텍스트에 있기 때문이다.

"그냥 짜줘"라고 하면 1회 확인 후 따르되 `overrides.log`에 기록한다. 자기 규칙은 자기가 깰 수 있어야 하지만, 기록이 있어야 회고에서 신호가 된다.

### review — 직접 설명 게이트 + 깊은 질문

- **Phase 0**: 코드가 어떻게 동작하는지 본인 문장으로 설명하게 한다. AI의 대필·초안·다듬기 일절 금지. 설명이 막히는 지점이 곧 위임했지만 이해하지 못한 지점이다.
- **Phase 1**: 엣지 케이스 / 코드 퀄리티 / 보안 세 카테고리에서 이 코드에 실제로 해당하는 질문만, 답이 아니라 질문으로, 한 번에 한 카테고리씩 던진다.

### init-notion — 구현 방식 기록 (선택)

Notion 작업 DB에 '구현 방식'(직접/위임/혼합) select 속성을 설정한다. **전부 선택 사항이며 exam/review는 Notion 없이 완전히 동작한다.**

## 사용 흐름

```
[프로젝트 최초 1회]
baseline 스킬 → 경계선 설정

[평소 작업]
구현 요청 → exam이 baseline과 대조
  ├─ 위임 구간   → 평소처럼 AI가 구현
  ├─ 혼합 구간   → AI 초안 → 직접 재작성
  └─ 직접 구간   → 출제 (요구사항·시그니처·테스트 케이스)
                   → 직접 구현
                   → 새 세션에서 review 실행
                      → Phase 0: 직접 설명
                      → Phase 1: 깊은 질문
```

## 프로젝트에 생성되는 파일

```
<프로젝트>/.claude/growth-with-ai/
├── baseline.md          # 위임 경계선
├── config.json          # Notion 연동 정보 (선택)
├── exams/<slug>.md      # 출제 명세 (세션 간 인계용)
├── overrides.log        # 규칙 우회 기록
└── unclassified.log     # 미분류 유형 누적
```

스킬에는 절차만 있고, 프로젝트별 판단 기준은 전부 `baseline.md`에 산다. 그래서 어떤 프로젝트에도 붙일 수 있다.
